# Voice starts and interrupted model usage (#331, #332)

The ledger now distinguishes completed calls, incomplete calls, and acknowledged Live session starts. Migration 0070 adds one nullable column and an allowed-value check after attachment migration 0069. Historical rows retain null lifecycle evidence; their tokens, billing identities and costs are unchanged. Null token counters remain unknown and are never estimated from partial text or replaced by message totals.

The stream wrapper records at most once per provider call, including source close, source error and consumer cancellation before a finish event. It forwards stream parts, errors and cancellation reasons. A finish retains the provider's reported counters; an error finish is marked incomplete. A stream cancelled or dropped without counters records nulls. Hermes' intentional skipUnknown policy omits only clean unknown-counter completion/approval pauses; interrupted Hermes streams retain an incomplete row with unreported runtime identity. Subscription/unknown routes still cannot acquire API dollar estimates.

When the company native budget is enabled, the outer usage wrapper owns the stream's ledger row while the inner budget wrapper retains interrupted reservations. The budget wrapper still records dispatch failures before a stream exists. This prevents duplicate incomplete rows and does not refund uncertainty or relax admission.

Each acknowledged OpenAI Live start records purpose `voice`, lifecycle `started`, the authenticated caller/chat, the actual OpenAI transport app, and the saved connection/organization/project used for that request. A Hermes backend does not relabel the OpenAI voice transport as Hermes-funded. Only an acknowledged session ID proves a start; failed or unacknowledged requests do not claim one. An acknowledged ID remains counted if its transport answer is invalid. Audio usage is not reported by this start contract, so tokens and cost remain null. Capturing final Live token counters is a separate provider reporting integration.

The admin dashboard and CSV expose observed call, incomplete-call and Live-start counts. Hosted search execution observations do not count as additional model calls, and assistant message counts remain separate. A null-token session contributes its count while token sums include only reported counts; the dashboard explains that this does not imply zero cost.

Validation uses local synthetic SDK/protocol boundaries, a historical-schema upgrade, and an exclusive opt-in PostgreSQL database. The real PostgreSQL proof loads the actual saved provider connection without calling OpenAI, verifies immutable historical billing selectors, and cancels a synthetic SDK stream while preserving its actual budget reservation and a single null-token ledger row with application pool=1. CI requires these and the existing usage aggregation proof. No live providers, audio sessions, Docker containers, account configuration or native apps are used.

Parity: web, iOS and macOS start voice through the same API and share server-side accounting. Only the web admin dashboard/CSV has a Usage surface; native clients have no equivalent administrator screen. No native voice API response or UI changes are required.
