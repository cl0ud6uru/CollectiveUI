# Copied bot delegates (#321)

A private copy keeps only delegates that the copier can access under the existing bot authorization rules, that use a portable engine, and that are not service bots. Owner-private delegates without access, local/native-only engines, model-less engines and Team Bots are omitted. Accessible public, copier-owned, explicitly granted and portable remote Hermes delegates remain linked. The source bot and its delegate links are unchanged.

This permissive delegate handling applies only while creating a copy from a snapshot. Explicit create/edit selections still fail their existing access, portability and service-bot checks. Source access, source connection availability and bot creation policy stay mandatory. Unexpected operational/database errors propagate; a partial copy is not reported as successful after such a failure. No provider, model inference or native daemon is invoked.

Regression evidence uses the actual duplicate/create/update server actions, real schema migrations and authorization/relation queries in embedded PostgreSQL (PGlite). Only the session and Next cache boundary are mocked. The authorization wrapper delegates to the production implementation except for one deliberate database-failure injection. All fetch calls are prohibited. Vector columns use arrays in this fixture; vector search, connection locking and external engines are not claimed as tested.

Before repair, three copy regressions failed with the original access/portable-engine errors; eight strict-validation/permission/error cases already passed. After repair, 12/12 cases pass, including an added explicit-user-access positive. Source relations/profile preservation, empty surviving delegate sets, portable delegate retention, strict editor behavior, source connection/access rejection, creation policy and operational-error propagation are covered. Typecheck, changed-file ESLint and diff checks pass.
