# Provider spending and subscription accounting

The administrator/IT boundary is the repository's existing `Principal.isAdmin` role (`requireAdmin` / `assertAdmin`). Members cannot read billing configuration, snapshots or refresh endpoints. `/admin/spending` is off until a separate billing account is configured and enabled. The optional model-header bar is also off by default and opens the organization dashboard; it does not imply that the selected model uses that billing account.

A billing key belongs only to `provider_billing_accounts`. It cannot be selected by models, bots, tools, provider inference, personal allowance, CSV or browser exports. AES-GCM AAD binds its ciphertext to the billing row and immutable organization ID. The browser receives an explicit metadata/snapshot whitelist. Key rotation uses ciphertext CAS. No real billing key was collected or created during development.

Provider reads are GET-only to the fixed public `https://api.openai.com/v1/organization/` origin, with redirects refused, bounded response parsing and request timeouts. The Costs query uses UTC month start (inclusive), request time (exclusive), 1-day buckets and bounded pagination. Organization totals and project breakdown are fetched independently. Missing currency/amounts, malformed pagination, inaccessible limits and unsupported intervals stay unknown. Limits are converted from returned cents to currency units; enforcement is shown exactly as returned. A 404 does not establish that a limit is unset. An explicit null result is displayed as unset. Provider reporting can lag; remaining allowance is a reported arithmetic value, not a promise of available spend. Project allowance is capped by the applicable organization allowance; if either is unknown it stays unknown. No prepaid balance or plan balance is claimed.

A failed Costs refresh keeps the last successful snapshot and its original timestamp. Failed refresh, 15-minute age, or a different UTC month makes the current allowance unknown. Refresh publication checks the account revision and enabled state, so an in-flight response cannot repopulate a disabled/rotated account. Each account has an independent one-minute refresh claim. Project limits are retrieved for configured saved provider connections with the exact organization selector; additional projects in the authorized breakdown retain unknown limits until configured. No provider limit is changed and no new local dollar cap is enforced.

Each new model ledger event copies the dispatch connection ID, organization and project selectors plus billing route. History never joins current model configuration to reassign spend. Old events are deliberately not backfilled with today's connection. ChatGPT-plan calls, including delegated and background receipts, keep token activity and have no API-dollar estimates. Unverified Hermes upstream billing also stays unknown and is excluded from dollar estimates. Verified native Team personal/admin dispatch already distinguishes billing source; this change preserves that route on its receipts. Classification never uses a model name. A DB constraint prevents non-organization, ChatGPT or unverified Hermes rows carrying `cost_micros` or search-fee estimates. The migration clears only those erroneous local monetary fields and preserves tokens, identities and historical receipts. Admin Usage CSV keeps token/call activity; its existing search-fee estimate is defensively filtered by billing source and route provider. Provider dashboard costs come only from the Costs API, never from that local ledger.

## Verified contracts (2026-10-08)

- [Organization spend limit](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/spend_limit/methods/retrieve): threshold cents, monthly interval, currency, enforcement.
- [Project spend limit](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/projects/subresources/spend_limit/methods/retrieve): separate project threshold and enforcement.
- [Costs](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs): currency-bearing amounts, daily buckets, project grouping and pagination.
- [API Platform Admin keys](https://help.openai.com/en/articles/9687866-admin-and-audit-logs-api-for-the-api-platform): organization owners select permissions in Platform settings; API Platform keys are separate from ChatGPT workspace Admin keys.
- [Admin key creation reference](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/admin_api_keys/methods/create): no exact restricted read-scope names were documented in the retrieved contract. This implementation does not invent scope names, create keys, or broaden permissions. Before separately authorized activation, verify the current Platform permission selections for Costs and organization/project spend-limit retrieval with the organization owner/OpenAI; use only the required read access. Scope verification remains an activation requirement.

No deployment, PR publication, live account connection, key creation, or provider inference is part of this implementation. Migration tests use disposable PGlite (pgvector mapped to arrays), not production PostgreSQL. Browser screenshots use synthetic provider data, and do not establish live provider conformance.
