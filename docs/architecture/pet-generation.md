# Admin pet generation

The optional image builder creates a private draft through three server-enforced stages: one appearance request, explicit appearance approval, then ten separately receipted sprite requests (nine animation grids and one 16-angle grid). Each animation result is cropped into the frames already defined by the Codex Pet v2 atlas. The combined 1536 × 2288 sheet is saved only after the existing v2 normalizer and occupied-cell validator pass. Before saving, the administrator reviews all nine states and sixteen directions using the shared animated PetPreview, including actual avatar sizes in light and dark themes, and records that visual review. Saving also requires a separate sharing confirmation and creates an unpublished catalog draft; publication remains a separate admin action.

The feature setting defaults to disabled and has no default provider connection. An administrator may select an existing enabled OpenAI company connection, but generation rejects disabled, non-OpenAI, or non-official endpoints. The model is fixed to `gpt-image-2.5-sunburst`, with one 1024 × 1024 low-quality transparent PNG request at a time. The saved connection's key is decrypted only for a request; the builder does not create or modify provider credentials. Automatic SDK retries are disabled.

The [official model page](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst) documents that model ID, endpoint, supported image generation and input, and lists image-input and image-output token rates of $8 and $30 per million respectively; text input is billed separately. The [image generation guide](https://developers.openai.com/api/docs/guides/image-generation) describes image and reference-image requests. These are usage rates, not a fixed image price: output size and detail affect token use, and this model's published calculator does not provide a fixed estimate for the current image-token consumption. The SDK exposes aggregate input and output token counts without enough category detail to calculate a defensible total for a reference-image prompt, so the receipt stores token counts and leaves exact cost null. The UI does not promise a quote or hard cap. Each retry has a separate confirmation; no retry occurs automatically.

Each job stores its owner, connection ID, fixed model ID, sanitized description, reference image, consent times, appearance state, and eventual catalog draft ID. Each provider request has an attempt receipt with prompt, slot, attempt number, cost-consent time, CAS-protected queued/running/succeeded/failed/uncertain state, result bytes, token counts, and error code. Requests are committed as running before network access. A lost reply or provider exception becomes uncertain, and a running receipt older than fifteen minutes is marked uncertain on inspection. Neither case is replayed. An administrator may explicitly authorize a new attempt for a failed or uncertain slot, at most three attempts total. Earlier receipts remain in the job history.

Admin role and session-version checks run inside receipt/consent mutation transactions and again immediately before a paid provider dispatch. If access is revoked after a claim but before dispatch, the generator is not called and the durable receipt is marked failed with `authorization_revoked`. Settings and their audit record are committed atomically.

This first slice is intentionally admin-only. The settings record retains selected/everyone and group/user fields for the next access phase, but the builder routes do not yet authorize ordinary members from those fields. Do not treat them as active grants. No provider request is made until an admin enables the feature, creates a draft, and explicitly consents at each paid stage.

The unit workflow test uses an injected synthetic image generator and embedded PostgreSQL migrations. It covers disabled-consent gates, one-shot claims, lost-reply recovery, explicit retries, the complete v2 assembly and validation path, and server enforcement of visual-review and sharing acknowledgements before unpublished draft saving, without calling OpenAI.
