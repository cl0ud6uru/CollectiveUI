# Admin pet generation

The optional image builder creates a private draft through three server-enforced stages: one appearance request, explicit appearance approval, then ten separately receipted sprite requests (nine animation grids and one 16-angle grid). A text description, a reference image, or both can define the appearance; an empty description is accepted only when a reference image is supplied. Each animation result is cropped into the frames already defined by the Codex Pet v2 atlas. The combined 1536 × 2288 sheet is saved only after the existing v2 normalizer and occupied-cell validator pass. Before saving, the administrator reviews all nine states and sixteen directions using the shared animated PetPreview, including actual avatar sizes in light and dark themes, and records that visual review. Saving also requires a separate sharing confirmation and creates an unpublished catalog draft; publication remains a separate admin action.

The feature setting defaults to disabled and has no default provider connection. An administrator may select an existing enabled OpenAI company connection, but generation rejects disabled, non-OpenAI, or non-official endpoints. The model is fixed to `gpt-image-2.5-sunburst`, with one 1024 × 1024 low-quality transparent PNG request at a time. The saved connection's key is decrypted only for a request; the builder does not create or modify provider credentials. Automatic SDK retries are disabled.

The [official model page](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst) documents that model ID, endpoint, supported image generation and input, and lists image-input and image-output token rates of $8 and $30 per million respectively; text input is billed separately. The [image generation guide](https://developers.openai.com/api/docs/guides/image-generation) describes image and reference-image requests. These are usage rates, not a fixed image price: output size and detail affect token use, and this model's published calculator does not provide a fixed estimate for the current image-token consumption. The SDK exposes aggregate input and output token counts without enough category detail to calculate a defensible total for a reference-image prompt, so the receipt stores token counts and leaves exact cost null. The UI does not promise a quote or hard cap. Each retry or replacement of a successful but unsatisfactory slot has separate confirmation; no image retry occurs automatically.

Each job stores its owner, connection ID, fixed model ID, sanitized description, reference image, consent times, appearance state, preview assembly error (if any), and eventual catalog draft ID. Each provider request has an attempt receipt with prompt, slot, attempt number, cost-consent time, CAS-protected queued/running/succeeded/failed/uncertain state, result bytes, token counts, and error code. Requests are committed as running before network access. A lost reply or provider exception becomes uncertain, and a running receipt older than fifteen minutes is marked uncertain on inspection. Neither case is replayed. An administrator may explicitly authorize a new attempt for a failed, uncertain, or successful-but-unsatisfactory sprite slot, at most three attempts total; a replacement invalidates the previous complete preview until rebuilt. Earlier receipts remain in the job history. If all request images are saved but atlas assembly/import fails, the saved slot images stay intact and an explicit nonbillable preview retry can rebuild them without another provider request.

Admin role and session-version checks run inside receipt/consent mutation transactions and again immediately before a paid provider dispatch. If access is revoked after a claim but before dispatch, the generator is not called and the durable receipt is marked failed with `authorization_revoked`. Settings and their audit record are committed atomically.

The feature setting defaults to disabled. An administrator selects the official company connection and configures access for everyone, selected portal groups, and/or selected UPNs. Every paid stage still requires a new explicit consent by the person who owns the private job; that owner's current group and session state are checked inside the durable claim and immediately before provider dispatch. Generation jobs and receipts are owner-scoped. Non-admins can assign a visually reviewed v2 result only to a private caller bot they can use; it is stored in the existing per-user private pet slot. Only admins can create shared catalog drafts, and publication remains a separate admin action with a distinct sharing confirmation. Turning the feature off prevents new paid dispatches; no provider request is made during configuration or page load.

The unit workflow test uses an injected synthetic image generator and embedded PostgreSQL migrations. It covers default-off and explicit-consent gates, selected-group authorization and current-membership revocation before dispatch, owner-scoped private assignment, non-admin publication denial, one-shot claims, lost-reply recovery, fresh-consent successful-slot replacement, reference-image-only appearance, nonbillable recovery from failed atlas assembly, the complete v2 validation path, stale-preview rejection under concurrent slot replacement, and server enforcement of visual-review and sharing acknowledgements before unpublished draft saving, without calling OpenAI.

Preview assembly and saving are bound to the latest successful receipt IDs under the job lock. A concurrent replacement invalidates the earlier assembly before it can become the visible or saved preview. Once a catalog draft exists, generation retry actions are rejected; catalog revisions use the existing catalog lifecycle.
