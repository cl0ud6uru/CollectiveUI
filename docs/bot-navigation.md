# Personal bot navigation

The Bots directory has a Pin/Unpin button for each bot you can use. Pins belong to your account, including for shared bots. Pinned bots stay at the top in your chosen order. A new pin appears after your existing pins; pinning a hidden bot also unhides it. Unpinning returns the bot to its recent-send position. Pinning never changes a bot's audience or configuration.

Drag a sidebar bot by its grip and drop at the insertion line to move it. On a keyboard or touch screen, activate the grip or the bot's options button and choose **Move up** or **Move down**. Moves retain pin state and work within pins or bots with equal recent-send timestamps (including never-used bots). Pin a bot to keep a chosen position regardless of recency. **Move up**/**Move down** step through your full saved order, including bots beyond the sidebar limit. A successful move is announced and focus returns to the moved bot's options button. Cancelling a drag leaves the arrangement unchanged.

The sidebar shows, with pins first and unpinned bots in recent-send order, every pinned bot plus the first five unpinned ones; **See all** opens the Bots directory when there are more. The bot you are chatting with is always shown, even when it is hidden or past the limit. The bot you just moved also stays in the sidebar until your next move or a page reload, even when the move takes it past the limit, so keyboard focus is never lost.

Order, pins and hidden state are saved to your account across refreshes, navigation, and later sessions. Opening a bot, assistant replies, group chats, routines, delegation, other users' messages and renamed bots do not reorder the list. Equal recent-send timestamps and never-used bots retain saved manual order. Newly accessible bots follow those with saved order when their recent-send timestamps match. Recent Chats keeps its own chronology.

On desktop, closing the sidebar leaves a 72px avatar rail. It uses each bot's selected identity, keeps the active bot highlighted, and fits up to six bots from the same recent-send arrangement into the available height. Bots beyond that capacity, including pins, remain in **All bots** in the same order. The active bot stays visible even when hidden or beyond the limit. Search the overflow by name, label or description, or use **Manage bots** for pins, ordering and hidden bots. **Hermes** opens native connections and history in either sidebar state and stays highlighted on its workspace pages. The mobile drawer keeps the expanded sidebar.

Hovering or focusing an avatar shows its name and confirmed activity. A purple ring indicates working state, an amber marker indicates approval or task failure/interruption, and a blue dot indicates a confirmed unread terminal task result. Idle bots never receive activity inferred from message previews or timestamps. Selecting a bot opens its home; it does not mark other task results read. Reduced motion removes the working ring's pulse. Overflow focuses its search field and returns focus to its trigger on Escape; short desktop windows can scroll the rail to reach every control.

Both surfaces update immediately while saving, and further changes are disabled until the save finishes. A failed save restores the saved arrangement and shows an error. Hidden bots can be shown again from the sidebar; their routines keep running. Deleted or inaccessible bots are filtered from the current authorized roster even if a saved preference references them. Pins never retain access.

Recency is recorded with each accepted direct bot-chat send in `users.prefs.botLastSentAt`, in the same transaction as the new user message and run. A rejected unsaved send does not promote a bot; a prompt saved before a queue/provider failure still counts. Regeneration and approval answers do not record new use. Copied shared history never counts as the viewer's send. For pre-existing history, only a user message with a matching foreground run admission timestamp counts; later regeneration cannot promote copied history. Newly recorded use survives deleting a chat. Old transcripts without a durable admission receipt retain the saved tie order until the next send.

Manual tie and pin order uses `users.prefs.botOrder`; pins and visibility use the existing `user_bot_prefs` table. Saving locks the signed-in user's row, verifies current permissions, and updates pins/order in one transaction while preserving unrelated preferences. No database migration is needed. Other users' preferences and the shared bot record are not modified.

Regression checks: `npm test` includes production admission and shell-query coverage with a migrated disposable PGlite database and a synthetic queue. `node tests/browser/bot-recent-use.mjs` checks real sidebar/provider components with synthetic local snapshots and no inference; set `BOT_RECENT_USE_SCREENSHOT_DIR` to a private path to retain expanded, collapsed and mobile evidence. Additional checks include the real-Postgres `tests/integration/bot-navigation.test.ts`. Browser checks use `BOT_NAVIGATION_BROWSER=1`, a migrated disposable database named `collective_navigation_test` on `127.0.0.1`, local authentication, and `npx playwright test --config tests/bot-navigation.playwright.config.ts` against the local app (default port 3121). These fixtures use synthetic accounts and do not make provider calls. The rail tests include selected avatars, active state, overflow search/focus and revocation, live task indicators, dark/light axe accessibility checks, reduced motion, 400px desktop height and the mobile drawer. Set `RAIL_SCREENSHOT_DIR` to a private directory to retain visual evidence outside the repository.
