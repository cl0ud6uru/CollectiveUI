# Voice session and task lifecycle

Starting voice in the same conversation resumes its connecting/connected session. Starting it in another conversation ends capture and saves the prior session before creating a new one. Ended saved sessions restart fresh; unsaved speech retains its retry session. Leaving the new chat during transition prevents new capture. A fresh connection listens first, with complete role-preserving historical messages supplied through Live `session.input` rather than replayed after startup.

Client delegation contains an ID and timeline offset, not the task text. The bridge retains transcript fragments, requires user evidence, and waits for delivery to settle before admission. User evidence near the delegation offset uses a 750 ms settling window; delegation after silence uses 1800 ms. Assistant acknowledgments cannot shorten that window. Newer user details beyond an early delegation boundary wait for a newer delegation. Continuing delivery beyond the 3 second admission deadline asks for clarification and retains speech for saving.

These are bounded delivery heuristics, **not proof of a completed utterance**. Live provides no completed-turn event and timestamps are approximate. A longer network delay can still arrive after admission. The backend remains responsible for clarifying missing details, checking current state, enforcing permissions, and obtaining required approvals. Reactions never admit a backend request or approve an action.

Backend requests retain durable batch identities. An unknown HTTP outcome retries the same identity. If a correction arrives before that retry, the retry is save-only: it can recover a run already admitted but cannot newly start the old action. The bridge serializes requests, waits through child-task work (`waiting_tasks`), and suppresses old result speech after newer user details or delegation. It does not cancel or reverse running physical actions merely because the caller speaks again. Existing chat controls and backend permissions remain authoritative; cancellation is not reported until verified.

Short verified result facts travel directly in commentary with the original delegation ID. Long results remain in chat, with a brief status directing the caller there. Append acknowledgments/errors are correlated without treating acknowledgment as proof of model uptake, playback completion, or tool success. Historical chat refreshes are deduplicated by message ID and text and do not replay partial backend replies during a pending task. Renderer and bridge expression state both reset to neutral for a new connection.

Automated checks use mocked media, transport, inference, and backend responses. Native build checks do not require installation. Real model adherence, Decisions latency, Home Assistant behavior, audio clicks, and physical-device performance require the next explicitly authorized device round.

Protocol references: [Live conversations](https://developers.openai.com/api/docs/guides/live-conversations), [Live delegation](https://developers.openai.com/api/docs/guides/live-delegation), and [Live prompting](https://developers.openai.com/api/docs/guides/live-prompting).
